## Experiment 1 — Full authenticated key establishment versus handover-token re-authentication

- **Research question:** Does mobility-aware token re-authentication reduce latency relative to a full V2R exchange?
- **Configuration:** Existing development run; one seed; values are recorded in seconds; no speed/density/suite sweep in this file.
- **Seeds:** 1.
- **Raw file:** `results/raw/handover_results.csv`.
- **Metrics:** Full latency, token latency, success, fallback.
- **Result:** Full = 18.3517 ms; token = 5.03833 ms; reduction = 72.55%; success = 1; fallback = 0.
- **95% CI:** Not available because only one run exists.
- **Baseline:** Full V2R authenticated key establishment.
- **Contribution support:** Directionally supports the latency-reduction contribution, but not statistically.
- **Missing/unsupported:** No repeated seeds, confidence interval, parameter sweep, or OMNeT++/Veins trace linkage.

## Experiment 2 — Factorial protocol-performance sweep

- **Research question:** How do speed, density, RSU spacing, PQC suite, malicious rate, and attack type affect protocol/network metrics?
- **Configuration:** Speeds 30/50/80 km/h; densities 50–300; spacing 250/400 m; ML-KEM-512/768/1024 paired with ML-DSA-44/65/87; malicious rates 0/5/10/20%; replay, forgery, Sybil, DoS, and false-position attacks; 20 seeds per configuration.
- **Seeds:** 20 per configuration; 43,200 seed-level rows; 2,160 grouped estimates.
- **Raw files:** `final_experiment_results.csv`, `final_experiment_summary.csv`, `crypto_metrics.csv`, `pbft_comparison.csv`.
- **Metrics:** All requested latency, cryptographic-time, overhead, throughput, PDR, consensus, detection, false-positive, and false-negative metrics.
- **Overall mean ± 95% CI:** Full latency 4.2845 ± 0.0033 ms; token latency 1.5399 ± 0.0013 ms; reduction 64.00 ± 0.02%; KEM encapsulation 0.5154 ± 0.0008 ms; KEM decapsulation 0.4668 ± 0.0007 ms; ML-DSA signing 0.3699 ± 0.0005 ms; verification 0.2641 ± 0.0004 ms; overhead 1,211.92 ± 1.75 bytes; throughput 143.56 ± 0.31 messages/s; PDR 0.8768 ± 0.0005; standard consensus 7.3229 ± 0.0113 ms; reputation consensus 6.4351 ± 0.0096 ms; detection 0.9060 ± 0.0007; FPR 0.0269 ± 0.0001; FNR 0.0983 ± 0.0007.
- **Baseline:** Full exchange for latency; standard PBFT for consensus.
- **Improvement:** Overall simulated consensus reduction = 12.12% (7.3229 to 6.4351 ms). The single-run PBFT artifact separately reports 14.60%.
- **Contribution support:** Supports only pipeline-level trends. It does not support final paper claims because the backend is stochastic development modeling rather than OMNeT++/Veins execution.
- **Missing/unsupported:** No real CAV traces, no paired network runs, no measured cryptographic timings for all three suites, no p-values/effect sizes, and no 30-seed production sweep.

## Experiment 3 — PBFT versus reputation-based PBFT

- **Research question:** Does reputation-aware grouping reduce consensus latency and isolate malicious nodes?
- **Configuration:** 13 nodes, `f=4`, quorum 9, 5 rounds, alpha=1, beta=5, gamma=2; three malicious nodes in the existing C++ development run.
- **Seeds:** 1 for `pbft_results.csv`; the factorial sweep contains 20 stochastic seeds/configuration.
- **Raw files:** `results/raw/pbft_results.csv`, `results/raw/pbft_comparison.csv`.
- **Metrics:** Consensus latency, phases, eligible/quarantined/revoked nodes.
- **Result:** Single run: standard 36.3343 ms; reputation-aware 31.0289 ms; reduction 14.60%; 3 quarantined and 3 revoked nodes in the adaptive run.
- **95% CI:** Not available for the single C++ run.
- **Baseline:** Standard PBFT.
- **Contribution support:** Demonstrates implementation behavior, not statistically validated evidence.
- **Missing/unsupported:** No repeated C++/OMNeT++ seeds, attack-by-attack detection confusion matrix, or paired statistical test.

## Experiment 4 — ProVerif verification

- **Research question:** Do the symbolic protocol models establish secrecy and correspondence properties under the Dolev–Yao attacker?
- **Configuration:** `v2r_handshake.pv`, `handover_token.pv`, and `v2v_session.pv`; ideal symbolic ML-KEM/ML-DSA equations, fresh values, protected long-term keys, and authenticated RSU channel assumptions.
- **Seeds:** Not applicable.
- **Raw files:** ProVerif source models; no CSV output.
- **Metrics/results:** V2R: 4/4 queries true. Handover: 4/4 true. V2V: 5/5 true.
- **Baseline:** Symbolic attacker model, not a performance baseline.
- **Contribution support:** Supports the stated symbolic secrecy/authentication claims under the documented assumptions.
- **Missing/unsupported:** Formal verification does not establish implementation correctness, concrete cryptographic timing, mobility performance, or statistical detection accuracy. The secrecy probe is symbolic; derived keys are linked through event correspondences.

## Overall audit conclusion

The repository has reproducible development artifacts and successful symbolic verification. It does not yet contain statistically defensible real-network evidence. Numerical claims in a networking letter must remain provisional until the stochastic sweep is replaced or cross-validated with instrumented CAV traces and paired OMNeT++/Veins runs using at least 20–30 seeds.
